# Главная PERK по структуре Ozon Seller

Референс: локальное видео IMG_9266.MP4, 24 октября 2026. Меняется только главная.
Палитра PERK, типографика, токены, общие компоненты и нативные вкладки сохраняются.

## Что используется сейчас

| Блок                     | Источник                                            | Поведение                                                                                |
| ------------------------ | --------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Магазин в шапке          | WorkspaceProvider / StoreSwitcher                   | Один магазин или все магазины текущего пространства                                      |
| Поиск                    | Заглушка                                            | Поле без ввода, пометка «Скоро»                                                          |
| Срочные поставки         | inventory/replenishment                                  | Позиции FBO с запасом до 7 дней по нативной истории WB; это потребность, не созданная поставка        |
| Стоимость хранения       | business → finance.summary.wb_expenses.paid_storage | За 30 завершённых дней; null остаётся прочерком                                          |
| Заказано / выкуплено     | insights/funnel → daily                             | Заказы и выкупы относятся к дате заказа; поздний выкуп изменяет прежний день             |
| Сравнение периодов       | Два соседних периода одной длины из того же daily   | Decimal, процент только при полном покрытии обоих периодов и ненулевой базе              |
| Финансы                  | business за 30 дней                                 | Выручка; расходы = выручка − прибыль до налогов только при полном подтверждённом расчёте |
| Реклама                  | Отложена                                            | Блок скрыт; раздел оставлен для будущих обновлений                                       |
| Количество на складах    | inventory/overview                                  | Отдельно ФБО и ФБС; неизвестный канал остаётся прочерком                                 |
| Стоимость склада         | inventory/overview                                  | По текущей цене продавца после его скидки, отдельно ФБО/ФБС; частичная сумма помечается  |
| Запланировано к поставке | Следующий этап                                      | Не выводится: supply-plan считает рекомендацию, но не хранит утверждённый план           |

График: «Неделя» (календарная неделя, содержащая вчера), 7/14/28 завершённых дней.
Режимы: с выкупленными / с прошлым периодом; сумма / штуки. Фильтры применяются кнопкой.
Всплывающая подсказка показывает дату, сумму и количество. Неизвестные дни не превращаются в нули.
Стандартные периоды существующих подробных страниц не меняются.

Воронка сообщает валюту. Суммы магазинов складываются только при одинаковой известной
валюте; при разных или неизвестных валютах доступны количества. Неизвестные магазины
сохраняют признак неполноты.
Выручка, операционные суммы заказов, выкупы и остаток баланса — разные показатели.
Снимки и ETag хранятся в ключах пользователя/пространства/магазина/периода; поздние ответы
другого магазина не используются. Ошибка API не подменяется тестовыми данными.

## Следующая работа

Базовая страница «Остатки» готова. Следующие улучшения согласовываем отдельно:

1. Остатки: фильтр по складам, сортировка и общий итог «в пути к покупателям / обратно».
2. Развитие оценки склада и истории: динамика стоимости, непроценённые размеры и экспорт.
3. Поставки: сохраняемый план с датой, статусом и количеством; отдельно оставить
   рекомендованное пополнение существующим POST inventory/supply-plan.
4. Расширение оборачиваемости: выбор окна и динамика. Текущий расчёт за 28 дней
   требует полной истории ФБО/ФБС; days_of_cover остаётся другим показателем.
5. Общий поиск: товары, отчёты и разделы; API и экран результатов.
6. Хранение: текущие тарифы и прогноз; сейчас показывается фактическая известная
   сумма по финансовым отчётам.
7. При необходимости — общий overview-снимок и серверная агрегация воронки.

Рекламные кампании, расходы на рекламу и ДРР отложены до будущих обновлений
по решению пользователя. Демонстрационный рекламный блок скрыт с главной.
Сверка финансовых цифр с WB также отложена пользователем.

## Структура кода

- OverviewScreen — порядок секций и переходы.
- home/useHomeOverview — получение данных и состояния запросов.
- home/overviewMetrics — диапазоны, суммы, проценты, неизвестные значения.
- home/overviewDemo — сохранённые примеры для будущих этапов; сейчас не выводятся.
- inventory — базовая страница остатков, карточка товара и запрос каталога.
- home/components — карточки, столбчатый график и панель фильтров; стили рядом с компонентами.

## Источники аналитики и обновление

- Главная, заказы, выкупы, отмены и воронка используют только insights/funnel.
  Старые insights/orders и insights/buyouts не подмешиваются в эти экраны.
- Отмены и возвраты объединены. Показатель выкупов WB включает последующие возвраты;
  из него повторно ничего не вычитается. «Процент выкупа WB» — выкупы / (выкупы + отмены).
- Выручка, прибыль, расходы и хранение остаются финансовыми расчётами по финансовым
  отчётам. Финансовый раздел «Продажи» подписан «Выручка», чтобы не смешивать источники.
- Нажатие на ⓘ возле «Выкуплено» открывает короткое пояснение; закрывается крестиком,
  нажатием вне окна или системной кнопкой назад. Для новых пояснений есть InfoHint.
- В беке уже задано обновление funnel раз в 6 часов, перечитывание 30 дней и еженедельная
  сверка 90 дней. Способ загрузки по одному дню сохраняется; CSV и «Джем» не подключены.
- Это серверные задачи: приложение только читает снимки PERK с ETag. Нужны работающие
  worker, worker-heavy и beat, а также включённый funnel в расписании конкретного магазина.
  Для новых подключений источник уже включён в useConnectStore. Для старых кабинетов
  нужно проверить расписание; no_data не заменяется старыми продажами или нулём.
- При сравнении 28 дней нужны также предыдущие 28 дней. Проценты не показываются до
  полного покрытия сравниваемых диапазонов. Полнота загрузки не означает, что все заказы
  уже завершены: выкупы прошлых дней могут изменяться и после двух недель.

## Этап «Товары» — 2 ноября 2026

Вместо заглушки работает каталог: поиск по названию/артикулу/штрихкоду,
фильтры наличия и отсутствующей себестоимости, размеры, цвета после обновления
каталога WB, остатки по складам, один или все доступные кабинеты.
Добавлены ручная цена с датой действия, история цен по артикулу и общий XLSX-импорт.
Себестоимость и остатки имеют отдельные права доступа; менеджер без profit.read
не получает цены, историю или фильтр отсутствующей цены. Пагинация по 30 карточек,
список виртуализирован. Сохранение цены обновляет финансовые и товарные запросы.
Данные WB не меняются, текущая финансовая история не переписывается.

Текущий функциональный этап — остатки. Рекламная аналитика отложена до
будущих обновлений. Сверка финансовых цифр с WB отложена пользователем.

### Карточки товаров — 02.11.2026

- Каталог повторяет объединения площадки: WB `imtID`; адаптер Ozon `model_info.model_id`. Без ID товар показывается отдельно. Полного коннектора Ozon пока нет.
- Угадывание моделей по названию, артикулу и характеристикам отключено. Ручные объединения/разделения имеют приоритет и сохраняются на бэке.
- Фото переключаются свайпом и миниатюрами. При одинаковом цвете варианты различаются по артикулу/ID, а название выбранного варианта показывается при отличии от заголовка карточки.
- Список получает `catalogModels` с ключом кэша `product-cards-v2`; отдельные артикулы — `catalogProducts`. `grouping` имеет значения `marketplace`, `manual`, `single`.
- Исходные цены, остатки и финансовые идентификаторы не перепривязываются к группе.
- Контракт: `D:/code/PERK/BACK/docs/PRODUCT_MODELS.md`.

- Добавлен флажок «Показывать все варианты в ленте»: исходные артикулы карточки отображаются отдельными строками со своими фото, остатками и себестоимостью; размеры остаются внутри артикула. При открытии сохраняется полная карточка и сразу выбран нажатый вариант.
- Флажок — только настройка вида ленты. Поиск, фильтры и пагинация продолжают выбирать карточки площадки; раскрываются все варианты этих карточек. Число артикулов берётся из `total_products`.
- Настройка хранится локально отдельно для каждого пользователя; по умолчанию выключена. Дополнительных запросов к API при переключении нет.

## Базовая страница «Остатки» — 2 ноября 2026

- Переход с главной через «Остатки» или «Все остатки»: `/reports/stock`.
- Источник — существующий `catalogProducts`: один или все доступные магазины,
  серверные итоги количества единиц и артикулов, поиск по названию/артикулу/штрихкоду,
  фильтр наличия и подгрузка по 30 артикулов. Итоги учитывают текущие фильтры.
- Лента показывает фото, цвет, размеры и остаток каждого артикула. В окне товара —
  галерея фото, все размеры, разбивка по складам и товары в пути по данным API.
- Используется общая настройка идентификатора: артикул продавца, WB или штрихкод.
- Доступ требует `inventory.read`; ключ запроса включает пользователя, пространство,
  магазин, права и фильтры. Стоимость и финансовые данные экран не запрашивает.
- Неизвестное количество отображается как «—», известный ноль — как 0.
  Неполные и устаревшие данные обозначаются. Периодическое обновление не заменяет
  список экраном загрузки; ручное обновление доступно потягиванием вниз.
- Оценка стоимости, утверждённые поставки и прогнозы не имитируются тестовыми числами.
  С главной убраны прежние примеры стоимости склада и планируемой поставки.

## Сводка ФБО/ФБС — 2 ноября 2026

Список товаров вынесен в `/inventory/products`. `/reports/stock` показывает
только сводку: стоимость и количество отдельно ФБО/ФБС, общую оборачиваемость,
остатки по себестоимости с явной пометкой неполноты. Шапка повторяет финансовый
раздел; нативная пустая шапка скрыта, фиксированные отступы списка убраны.

На главной также показаны суммы, количества ФБО/ФБС, общая стоимость остатков
и оборачиваемость. Запрос общий для главной и сводки. Цены — после скидки продавца,
без скидки WB; прошлые продажи не подставляются вместо текущих цен.
Стоимость по себестоимости доступна только с соответствующим правом.

Бэк: отдельные атомарные импорты цен и ФБС, история по каналам, валютная проверка,
расчёт оборачиваемости по среднему остатку и выкупам из воронки за 28 дней.
До накопления полной истории показатель остаётся прочерком. Для цен и ФБС нужен
read-only ключ WB с дополнительными категориями. Доступность не имитируется.
Подробный контракт: `D:/code/PERK/BACK/docs/INVENTORY_OVERVIEW.md`.


## Запас в днях WB — 2 ноября 2026

Старый расчёт через средний локальный остаток/выкупы заменён. Источник WB
«История остатков» отдаёт текущий запас, заказы и время отсутствия сразу за
прошлые 28 дней. Ожидания 28 дней после подключения нет. Отдельный импорт
`stock_history`, обновление раз в 6 часов, автоматическое включение для новых
и существующих магазинов с активной синхронизацией остатков/воронки.
Главная, сводка и карточки показывают «Запас в днях»; пояснение — под кнопкой i.
Ozon оставлен на отдельный этап. Подробная формула и ограничения:
`D:/code/PERK/BACK/docs/INVENTORY_OVERVIEW.md`.


## Мобильные поставки — 3 ноября 2026

Внутри «Остатков» добавлены общая оценка потребности FBO, три срочные позиции,
полный список потребности и существующие поставки WB с датами/количествами/статусами.
Детали открываются в BottomSheet. Нижние вкладки не менялись.

Потребность: 30 дней после поступления, срок поступления 7 дней; оценка по артикулам,
без вычета запланированных поступлений и коробной кратности. Новые импорты
supply_demand (FBO, 6 часов) и supplies (1 час) выполняются фоном на сервере.
Мобильный экран и главная используют одну срочность. Нужен read-only ключ с
категорией «Поставки» для готовых поставок; отсутствие категории объясняется в блоке.

Для сайта остаются конструктор планов, целевой срок/сроки поступления, распределение,
короба и экспорт шаблонов. Создание собственных планов PERK и согласование их
сотрудниками ещё не реализованы; список в приложении показывает поставки из WB.


## Упрощение экранов — 3 ноября 2026

- «Остатки» и «Поставки» — отдельные пункты в «Ещё». Карточка поставок на главной
  открывает /supplies, карточка остатков — прежний /reports/stock.
- В «Поставках» по умолчанию рекомендации. «Поставки WB» — отдельная вкладка

- Список рекомендаций содержит все позиции с потребностью, срочные идут первыми.
- Себестоимость встроена в верхние карточки FBO/FBS, отдельного блока нет;
  доступ к себестоимости остаётся под profit.read.
- Повторяющиеся статусы полноты/давности, фонового обновления и предварительности

  доступны через InfoHint. Неизвестные значения остаются прочерками, не нулями.
- Расчёты и API не менялись; ошибок запросов, доступа и первой загрузки это не скрывает.


## Фильтр поставок по кабинетам — 5 ноября 2026

В режиме «Все магазины» на экране поставок можно выбрать кабинет, не меняя
общую настройку приложения. Верхняя карточка сохраняет потребность всего бизнеса
в штуках и позициях; рядом с фильтром показана потребность выбранного кабинета.
Рекомендации и история поставок WB фильтруются на сервере до пагинации через
существующий store_id. Кеш страниц разделён по кабинетам, пользователю и правам.
Итоги берутся из сводки API, а не из суммы первой загруженной страницы.
Позиции разных кабинетов не объединяются по названию или артикулу.


## Параметры поставок на сайте — 6 ноября 2026

Для рекомендаций WB/Ozon доступны целевой запас 1–180 дней и доставка/приёмка
0–90 дней. Начальные значения остаются 30/7. Параметры не запускают новый импорт,
расчёт использует уже опубликованные данные маркетплейса. Кратность коробов
сохраняется на сервере по компании, кабинету и товару; её учитывает общая потребность
и мобильные рекомендации. Изменять кратность может владелец/администратор.

CSV потребности содержит все строки, а не только открытую страницу; учитывает
выбранный кабинет и фильтр срочности. У сотрудника должны быть inventory.read
и reports.export. Артикулы и штрихкоды сохраняются как текст; формулы из названий
не исполняются. Это отдельный отчёт потребности, не формат загрузки в WB/Ozon.

Следом остаются собственные планы, кластеры на подтверждённых данных площадок,
распределение количества по размерам/штрихкодам и проверенные шаблоны загрузки.
Оформленные и находящиеся в пути партии пока не вычитаются из рекомендации.
