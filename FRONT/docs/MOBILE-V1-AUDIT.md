# Аудит первой мобильной версии PERK · 4 ноября 2026

Проверены исходники текущего фронта и бека, связи модулей, запросы, права, схемы,
зависимости и автоматические проверки. Выполнена реорганизация исходников и исправлены
найденные проблемы. Это инженерный аудит; денежные цифры не сверялись с кабинетом WB.

## Результат

| Область           | Изменение                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Структура клиента | Экраны, компоненты, хуки, расчёты и провайдеры разложены по соответствующим папкам внутри разделов. Стили остаются в компонентах                              |
| Поставки          | Собственная `features/supplies` на фронте и `modules/supplies` на беке; экран остатков не содержит поставки                                                   |
| Навигация         | Реализация «Ещё» вынесена в feature; маршруты ссылаются на экраны, общая шапка — в `components/navigation`                                                    |
| Общая логика      | Один `useStoreScope` для области запросов остатков/поставок; один debounce для поиска товаров и остатков, пробелы нормализуются до формирования ключа         |
| Чтение бека       | Общий tenant-фильтр вынесен из финансов в `db/tenant`; зашифрованные записи и состояния источников — в `sync/read`                                            |
| История загрузок  | Вместо всех старых запусков читаются только последние успешные и активные состояния нужных источников с явным ограничением по пространству/магазину           |
| Каталог           | Убран вложенный перебор всех складских размеров для каждого товара; размеры индексируются по артикулу                                                         |
| Сводка остатков   | Не строятся карточки, списки складов и подсказки, которые не входят в ответ `limit=0`                                                                         |
| Потоковые записи  | Чтение двух нужных столбцов без создания тысяч промежуточных ORM-объектов; шифрование и RLS сохранены                                                         |
| Значения остатков | Исправлена ошибка: пустые позиции больше не превращают неизвестную стоимость непустого остатка в `0 ₽`. Настоящая нулевая себестоимость по-прежнему допустима |
| Диагностика       | Сбой постановки обновления сводки в очередь теперь фиксируется без секретов в журнале; предыдущий отчёт остаётся доступен                                     |
| Зависимости       | Убраны пустые пакеты config/hooks/types/ui и неиспользуемая библиотека gifted-charts; исправлены доступные совместимые уязвимые версии                        |
| Документация      | Обновлены README, карта архитектуры и статус бека; прежнее описание сохранено в архиве                                                                        |

Карта папок: [ARCHITECTURE.md](ARCHITECTURE.md).
Схема сервера: [BACK/ARCHITECTURE.md](../../BACK/docs/ARCHITECTURE.md).
Формулы спроса, бухгалтерские формулы и источники WB не менялись.
Публичный OpenAPI совпадает с прежним, новая миграция не требуется.

## Проверки

- 160 тестов фронта: сессия, HTTP, refresh/logout, кэш, периоды, графики, доступ и формы.
- 482 теста бека в отдельной PostgreSQL/Redis после обновления зависимостей:
  финансовые сценарии, синхронизация, RLS/роли и новые регрессии аудита.
- TypeScript, ESLint, Ruff и Bandit. Проверяется совместимость Expo SDK 58.
- Экспорт JS/Hermes-бандлов и ресурсов Android/iOS/web прошёл на окончательных зависимостях. APK/IPA в этом аудите не собирались.
- Новый и старый отчёты на одних сохранённых данных совпали по всем полям, кроме
  исправленных `cost_value` FBO/FBS/total: неизвестное значение вместо ошибочного нуля.

Полный сценарий приложения на физических телефонах в этом аудите не проходился.
Автоматические проверки и сборки не заменяют такую проверку.

## Производительность

Локальный замер одного текущего магазина, по три вызова сервиса, медиана;
это время чтения на сервере, без HTTP, сети телефона и первой загрузки из WB.

| Измерение                                      |     До |  После |
| ---------------------------------------------- | -----: | -----: |
| Прочитано объектов истории при сводке остатков |    275 |      7 |
| Прочитано объектов истории каталога            |    121 |      2 |
| Прочитано объектов истории рекомендаций        |      4 |      1 |
| Сводка остатков                                | 535 мс | 526 мс |
| Страница остатков                              | 554 мс | 528 мс |

Разницу времени нельзя считать доказанным ускорением: это один магазин, замеры
не были нагрузочным экспериментом. Главное подтверждённое изменение — ограниченный
объём истории, который больше не растёт с числом успешных загрузок.
Сводка всё ещё расшифровывает около 10 тысяч записей; для заметного дальнейшего
ускорения стоит готовить агрегат остатков в фоне с версией данных и проверкой прав.
Новый слой долговременного кэша в рамках реорганизации не добавлялся.

## Зависимости

Обновлены Zod приложения/общих пакетов до 4.6.6, node-forge до 1.4.2,
follow-redirects до 1.16.2; Python dnspython 2.9.2, filelock 4.2.8,
opentelemetry-api 1.45.2. Зафиксированы lock-файлы, проверены контейнерные зависимости.
В Python проверка известных уязвимостей после обновления — без находок.

Выполнено совместимое обновление в рамках **Expo SDK 58**: Expo 58.0.23,
React Native 0.88.1, Router 58.0.30 и рекомендованные версии нативных модулей.
Metro согласован с RN 0.88.1. `expo install --check` и `pnpm peers check` проходят.

`pnpm audit --prod` теперь показывает **2 умеренных предупреждения**, без high/critical:

| Пакет инструментария Expo | Уровень  | Что осталось                                                                                                              |
| ------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------- |
| minimatch 10.2.6          | Moderate | [Advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249): исправление требует major 11 за пределами текущего дерева  |
| glob 13.0.6               | Moderate | [Advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4): исправление требует major 14 за пределами ограничений Expo |

Изначально было 17 advisories фронта, включая 8 high; после совместимых обновлений
остались эти два. Принудительная подмена major-версий через overrides не добавлялась.
Проверка относится к известным уязвимостям production-дерева; это не гарантия
отсутствия всех возможных проблем. Предупреждения закроются совместимым обновлением инструментария.
