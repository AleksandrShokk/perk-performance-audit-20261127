# PERK Web

Личный кабинет на Next.js App Router: аналитика WB/Ozon, финансы, товары, остатки,
поставки и настройки компании. Данные поступают из существующего API PERK.

## Запуск

Из `D:\code\PERK\FRONT`:

```powershell
pnpm install
pnpm web dev
```

Адрес: http://localhost:3000. На порту 8000 должен работать существующий API PERK.
Порт 8081 остаётся у Expo. Не запускайте два экземпляра сайта на порту 3000.

Необязательная настройка — скопировать `.env.example` в `.env.local`:

```dotenv
API_ORIGIN=http://127.0.0.1:8000
NEXT_TELEMETRY_DISABLED=1
```

API_ORIGIN читает только сервер Next.js. Браузер вызывает `/api/v1` на адресе сайта;
Next.js передаёт эти запросы существующему FastAPI. Origin сайта должен быть разрешён
в настройках бэка; localhost:3000 уже разрешён в локальной конфигурации проекта.

## Структура

- `src/app` — тонкие маршруты: главная, вход, регистрация, восстановление, подтверждение, телефон.
- `src/features/auth` — браузерная сессия и формы авторизации.
- `src/features/workspace` — компании, кабинеты, права и подключение магазина.
- `src/features/overview` — график с переключением метрик, правая панель, финансовая сводка и таблица с вкладками.
- `src/features/finance` — полный финансовый отчёт, внесение расходов, импорт себестоимости и налоговые настройки.
- `src/features/products` — каталог карточек WB/Ozon, варианты, фото и редактирование себестоимости.
- `src/features/inventory` — сводка FBO/FBS, оценка остатков, таблицы товаров и кабинетов, детализация размеров и складов.
- `src/features/supplies` — потребность FBO, рекомендации, фильтр кабинетов и оформленные поставки WB/Ozon.
- `src/features/analytics` — воронка, график и сравнение периодов, поиск/сортировка товаров и карточка показателей.
- `src/features/settings` — кабинеты, команда и профиль.
- `src/features/team` — принятие приглашений и сохранение ссылки на время регистрации.
- `src/features/sections` — сохранённый шаблон для будущих разделов.
- `src/components/ui` — компоненты shadcn/ui на Radix.
- `src/components` — общая оболочка, обратная связь и постраничные диалоги.
- `src/hooks` — общий кеш воронки для главной/аналитики, задержка поиска и обновление компании.
- `src/lib` — HTTP, ошибки и несекретные настройки интерфейса.

Общие пакеты монорепозитория:

- `@app/api` — сгенерированные типы/запросы, общий Axios.
- `@app/schemas` — формы и русские сообщения Zod.
- `@app/tokens` — палитры/размеры/типографика; ThemeTokens превращает их в CSS-переменные.
- `@app/analytics` — существующие чистые функции периодов, сводок графика,
  форматирования и прав. Мобильные пути совместимы через реэкспорты.

## Что работает

Вход с email/телефоном и вторым фактором; резервные коды; регистрация с почтой,
телефоном и копированием всех резервных кодов; восстановление пароля; выход.
Переключение компании/кабинета и общая сводка нескольких площадок.

Главная: 7/14/28 дней или свой период до 28 дней, суммы/количества,
заказы/выкупы/отмены, сравнение с прошлым периодом, проценты и выделение дня;
финансы за 30 дней с детализацией расходов; FBO/FBS и стоимость;
постраничные остатки по товарам, рекомендации и оформленные поставки.
Светлая, тёмная и системная темы. Подключение WB/Ozon с подтверждением действия.

Верхняя навигация ведёт на отдельные страницы `/analytics`, `/products`, `/finance`,
`/inventory`, `/supplies`. Финансы заполнены: 7/30/90 дней и свой период до 1100 дней,
таблица статей с детализацией, расходы, налоги, импорт себестоимости XLSX, экспорт
сводки CSV. Товары заполнены: поиск и фильтры, карточки площадок, варианты, галерея и история себестоимости.
Остатки заполнены: FBO/FBS, стоимость по цене продавца и себестоимости, запас в днях,
поиск, постраничная таблица товаров и сводка по кабинетам. В карточке — фото, размеры,
штрихкоды и склады. Итоги страницы не зависят от фильтров таблицы. Для смешанного
набора WB/Ozon запас в днях показан по кабинетам, без усреднения разных методов.
Разбивки по складам Ozon в текущем API нет: вместо выдуманных складов показано
пустое состояние. Учёт общих/раздельных FBS-складов настраивает администратор
при выборе нескольких кабинетов с Ozon.
Поставки заполнены: общая потребность, срочные позиции, отдельный фильтр кабинетов,
постраничные рекомендации и оформленные поставки WB/Ozon. Все строки открывают
детали. Фильтр списка не меняет сводку всего бизнеса. В рекомендациях используется
единый расчёт API WB/Ozon: запас после поступления от 1 до 180 дней и срок доставки
с приёмкой от 0 до 90 дней. Выбор сохраняется как настройка интерфейса отдельно для
пользователя и компании. Кратность коробов хранится на сервере для товара в кабинете;
владелец/администратор настраивает её кнопкой в столбце «В коробе». Потребность и общая
сводка округляются вверх, мобильный клиент учитывает те же сохранённые правила.
Выгрузка потребности CSV включает все страницы выбранного кабинета/фильтра и требует
права экспорта. Это отчёт, а не шаблон загрузки в кабинет маркетплейса.
Входящие партии учитываются по подтверждённому составу, датам и конечному складу.
Работают сохраняемые планы, распределение по нативным размерам, CSV и заполнение
исходного XLSX. Вкладка «По кластерам» использует кластеры Ozon и регионы WB;
требования разных направлений считаются независимо. Два предоставленных пустых
шаблона площадок проверены на заполнении; отправка в кабинеты не выполнялась.
 Аналитика заполнена: 7/14/28 дней и свой период до 28 дней, столбчатый график,
воронка и конверсии, сравнение с прошлым периодом, продажи/воронка по товарам,
поиск, сортировка и карточка показателей. Товарные подписи приходят из аналитического
API без доступа к каталогу. При ограничении API список подписан как топ товаров
(до 500 позиций на кабинет), общая сводка остаётся полной. Суммы разных валют
не складываются; общая таблица/график переключаются на количество. На главной таблица переключается
между топом товаров, остатками и поставками с постраничной загрузкой.
Изменения расходов, себестоимости и налогов применяются к явно выбранному кабинету
и обновляют финансовую сводку. История внешних расходов показывает все даты.

## Правила данных

Валюты/неизвестные значения обрабатываются общей функцией приложения.
Частичные суммы не превращаются в подтверждённые проценты. Запас в днях берётся
из готового API и не пересчитывается на сайте. Финансовые 30 дней независимы
от выбранного периода графика. Запросы площадок выполняются бэком в фоне.
При опросе готовых снимков страница не размонтируется, анимация столбцов выключена.

Сессия — HttpOnly cookies и CSRF. Один refresh на параллельные запросы;
смена аккаунта отменяет старые запросы и очищает кеш. Отчёты, токены и ключи
не сохраняются в localStorage: там только тема, выбранный кабинет и фильтры.
Права проверяются бэком, а интерфейс скрывает недоступные разделы.
Текущие локальные режимы доставки кодов на бэке сохранены.

## Настройки

Через меню профиля доступны `/settings` (кабинеты), `/settings/team` (команда)
и `/settings/profile` (профиль). Управление компанией доступно владельцу и администратору.
Подключённые и неработающие кабинеты видны вместе: переименование, проверка подключения,
замена токена WB или ключа Ozon для того же Client ID. Секреты не запрашиваются обратно.

Команда: приглашение на email, роль, отдельные права и кабинеты, повторная отправка,
отмена и удаление доступа. Владелец компании защищён от изменения. Ссылка ведёт
на `/invite#code=…`; приглашённый регистрируется с этим email и подтверждает телефон.
При такой регистрации собственная компания не создаётся. Одноразовое приглашение
временно хранится в sessionStorage; удаляется после принятия, отмены или выхода.

Профиль: смена пароля и выход на всех устройствах. Оба действия завершают текущую
сессию по контракту бэка. API списка отдельных устройств пока нет.
Для защищённых действий используется одно общее окно подтверждения с ручной
отправкой кода, отменой и проверкой актуальности ответа. Закрытие формы отменяет запрос.
В локальном Docker `TEAM_INVITE_URL` указывает на `http://localhost:3000/invite`.
Для перехода по письму с другого устройства потребуется доступный ему адрес сайта.

## Проверки

```powershell
pnpm check
pnpm web test:e2e
pnpm web build
```

`test:e2e` использует установленный Edge и перехватывает ответы API синтетическими
фикстурами только внутри тестового браузера. Демо-данных в приложении нет;
реальные аккаунты/маркетплейсы браузерные тесты не изменяют.
Unit-тесты проверяют CSRF, единственный refresh и отбрасывание старых ответов.

Для локальной проверки производственной сборки после остановки dev-сервера:

```powershell
pnpm web build
pnpm web start
```

Проект приватный. Развёртывание на внешнем сервере этим этапом не выполняется.
