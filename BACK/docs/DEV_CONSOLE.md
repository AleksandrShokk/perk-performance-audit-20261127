# Локальный экран PERK

Адрес: http://127.0.0.1:8010. Реальные данные одного подключённого магазина.
Четыре источника: каталог, продажи/возвраты, остатки FBW, финансовые строки.
Есть статусы, запуск загрузки с выбором дат/источников, таблицы с пагинацией и список полей.
Финансовые методы и ABC реализованы в основном API, но ещё не подключены к этому экрану.
Продажная аналитика доступна через локальную консоль. Поставки и реклама пока не реализованы.
Статус: [STATUS.md](STATUS.md).

Кнопка «Последние 90 дней» выбирает максимальную гарантированную историю продаж.
«Вся доступная история» при выбранных финансах выставляет начало 29.01.2024;
продажи автоматически получают последние 90 дней. Для уже активной задачи период
не меняется: он показан в карточке статуса. Остальные выбранные источники запускаются
независимо. Недоступные для типа токена источники отключены в выборе.

Первые полученные строки первой загрузки сразу видны с пометкой о неполном наборе и «+»
рядом со счётчиком. Это количество записей, а не итоговая выручка. При последующих обновлениях
экран сохраняет предыдущий полный набор до успешного завершения.

Таблицы читаются из базы PERK, без ожидания запросов WB. Переключение недавно открытых
страниц использует ограниченный кеш в памяти вкладки; данные не сохраняются в localStorage.
Пока загрузка идёт, экран проверяет прогресс каждые 5 секунд, в простое — каждые 30 секунд.
Новая страница запрашивается только при изменении состояния загрузки. Кеш очищается при 401.

## Доступ

Это отдельный локальный инструмент оператора, а не обычная пользовательская сессия.
Ключ `pd_…` не истекает на сервере до отзыва/ротации. Браузерная HttpOnly-cookie живёт
до года; после очистки браузера создайте новую ссылку, сам ключ менять не нужно.
Ключ лежит в `.secrets/dev-console/token.txt`, настройки доступа — в `grant.json` рядом.
Файлы не входят в Git или Docker-образ. Не публикуйте этот каталог.

При первичной настройке:

```sh
python -m scripts.dev_console init --user USER_UUID --workspace WORKSPACE_UUID --store STORE_UUID
docker compose -f compose.yaml -f compose.console.yaml up -d --build console
```

Новая одноразовая ссылка (5 минут):

```sh
python -m scripts.dev_console open
```

Откройте адрес из `.secrets/dev-console/open.url`. Код передаётся фрагментом URL,
удаляется из истории страницы, обменивается на HttpOnly/SameSite=Strict cookie и
сгорает после использования. Постоянный ключ не возвращается в JSON и не хранится
в localStorage. Для программного доступа допустим Bearer `pd_…` только на порту 8010.

## Ограничения

- Стенд запускается только с явным `DEV_CONSOLE_ENABLED=true` и `APP_ENV=local`.
  В production/test он отказывается запускаться. Обычный `compose.yaml` его не включает.
- Порт опубликован только на 127.0.0.1. Не меняйте привязку и не проксируйте его наружу.
- Контейнер присоединён к внутренней сети с базой/Redis и к обычной Docker-сети,
  чтобы Docker Desktop мог опубликовать порт на локальном компьютере.
- Разрешены просмотр данных и запуск импорта только указанного магазина. На каждом запросе
  проверяются активный аккаунт с настроенной MFA, роль owner и привязка магазина.
  Сам локальный ключ заменяет повторный ввод MFA на этом стенде — это намеренное
  исключение для разработки, не схема авторизации пользователей production.
- Обычный API на 8000 не принимает этот ключ. Изменение паролей, MFA, токенов WB,
  управление аккаунтами и доступ к произвольному workspace отсутствуют в стенде.
- Для браузера проверяются Host, Origin, CSRF; CSP запрещает сторонние скрипты.
  При ошибке Redis или удалении файла доступа запрос отклоняется.
- Сводка остатков считается целиком только до 5 000 позиций. Для большего объёма
  показано «—», таблица остаётся доступной. Отсутствие загрузки не обозначается нулём.

## Отзыв и завершение разработки

```sh
python -m scripts.dev_console rotate
python -m scripts.dev_console revoke
docker compose -f compose.yaml -f compose.console.yaml stop console
```

`rotate` выпускает новый ключ и отзывает старый; `revoke` удаляет только три файла
локального доступа. Ключи WB, шифрования и обычные пользовательские сессии не меняются.
Для production используйте основной образ/точку входа `app.main:app` без console override.
