# Остатки и запас в днях

`GET /api/v1/workspaces/{workspace_id}/inventory/overview` — общий read model
для главной, сводки и списка товаров. Проверяется `inventory.read`, себестоимость
доступна только с `profit.read`; RLS и разрешённые кабинеты применяются до чтения.

## Стоимость и количество

FBO/FBS: независимые атомарные импорты `stocks` и `fbs`, цена — `prices`.
Цена после скидки продавца, без скидки WB. Неизвестные цены/остатки не равны нулю.
`retail_complete`/`cost_complete` показывают полноту сумм; `stale` учитывает возраст
и остатка, и цены. Бар-коды-алиасы не умножают количество вариантов.

## Запас в днях — WB

Источник `stock_history`: `POST /api/v2/stocks-report/products/products`,
категория токена «Аналитика». Все товары, без фильтра доступности, обе модели
(`stockType=""`), включая удалённые карточки. Окно — 28 завершённых московских
дней, независимо от первоначальных 7 дней графика. Обновление раз в 6 часов.

Из ответа сохраняются только nmID, запрошенный период, `stockCount`,
`ordersCount`, `officeMissingTime` (дни и часы). Это уже история WB до подключения
магазина, поэтому локальные 28 ежедневных снимков не требуются. CSV по дням
скачивать для этой формулы не нужно. Готовый `saleRate` WB не подставляется:
он использует выкупы, а показатель PERK — заказы.

Для товара:

`дни наличия = 28 − officeMissingTime.days − officeMissingTime.hours / 24`

`заказов в день = ordersCount / дни наличия`

`turnover_days = stockCount / заказов в день`

Текущий остаток для этого расчёта берётся из того же отчёта WB, чтобы не смешивать
срезы. FBO/FBS-оценка стоимости по размерам продолжает использовать отдельные
импорты. Показатель отражает темп заказов, не бухгалтерские продажи; отмены не
вычитаются. Суммарный показатель — сумма запасов / сумма темпов заказов товаров
в наличии, не среднее их дней. Полностью распроданный товар не ускоряет продажу
других товаров. Товар в наличии без заказов остаётся в общем запасе. Товары с неизвестным темпом
или остатком исключаются из оценки с обязательным `turnover_partial=true` и
пометкой «По части товаров»; если нет достоверных строк, значение — `null`.

WB на практике возвращает отрицательное время отсутствия для некоторых товаров
(например, 0 дней, −4 часа, в том числе со статусом balanced). Такая длительность
остаётся неизвестной; она не заменяется нулём и не блокирует остальные товары.

Нет заказов, времени наличия или нужного поля — `null`, не 0.
У каждой позиции `turnover_status` объясняет значение:
- `ready` — рассчитан `turnover_days`, включая известный ноль;
- `no_orders` — WB подтвердил 0 заказанных единиц за полный 28-дневный период;
- `loading` — отчёт для позиции пока отсутствует, импорт выполняется;
- `no_data` — строки нет или данных для расчёта недостаточно.

Неизвестные заказы не превращаются в «Нет заказов». При фоновом обновлении
сохраняется предыдущий успешный результат. Отсутствие заказов можно показать
даже при неизвестном времени наличия: это самостоятельный подтверждённый факт.
 У распроданного
товара с известным положительным темпом — 0 дней. Дробные часы не округляются.
Старый API-ключ с «Аналитикой» не требует новой категории для этого отчёта.

Поля API `turnover_days`/`turnover_window_days` сохранены для совместимости.
В интерфейсе — «Запас в днях». `observed_days` теперь означает ширину импортированного
окна WB (28), не возраст подключения. `turnover_loading`, `turnover_updated_at`,
`turnover_stale` описывают загрузку/возраст отчёта отдельно от оценки стоимости.

## Публикация и ограничения

Пагинация по 1000 товаров, официальный лимит и Retry-After. Для Basic-токена
минимальный интервал 30 минут. Неполный или ошибочный импорт не заменяет предыдущий
успешный снимок; пустой полный ответ удаляет старые строки. GET не вызывает WB.
Миграция 0022 добавляет источник и план существующим активным импортам остатков/
воронки. Новые подключения включают его автоматически.

Исторические локальные `inventory_snapshots` сохранены: их используют остальные
инвентарные отчёты. Ozon на этом этапе не изменяется.

Документация WB: https://dev.wildberries.cn/docs/openapi/analytics
