# План интеграций WB и Ozon — 23 октября 2026

Обновление 04.11.2026: подключение Ozon реализовано. Актуальная последовательность — [OZON.md](OZON.md).

Источник: официальные спецификации из архива `marketplace-api-docs-2026-10-23`
(WB — 13 YAML от 23.10.2026, Ozon Seller/Performance — снимок от 18.10.2026).
Интеграции только читают данные: методы изменения цен, ставок, поставок и заказов
не вызываются, пока для них нет отдельного решения и подтверждения пользователя.

## Сделано

| Источник | Метод | Использование |
|---|---|---|
| Заказы WB | `GET statistics-api /api/v1/supplier/orders` | Заказы, отмены, средний чек, процент выкупа, спрос для прогноза остатков |
| Воронка WB | `POST seller-analytics-api /api/analytics/v3/sales-funnel/products` | По одному дню: переходы в карточку → корзина → заказ → выкуп; до 360 дней истории |
| Возвраты продавцу WB | `GET seller-analytics-api /api/analytics/v1/item-returns` | Окна по 31 дню, 1000 строк; типы/статусы/SKU, товары в ПВЗ со сроком хранения |

Заявки покупателей (`GET returns-api /api/v1/claims`, только последние 14 дней) требуют
категорию токена «Возвраты покупателями». В архиве документации нет соответствия этой
категории биту в токене; PERK сейчас отклоняет токены с неизвестными правами. Подключение —
после подтверждения бита (например, на тестовом токене только с этой категорией).

Особенности по документации: 1 строка = 1 единица товара, ключ — `srid`; хранение 90 дней;
обновление раз в 30 минут; лимит 1 запрос в минуту (у базового токена — раз в 3 часа);
постраничная выгрузка по `lastChangeDate`. Заказы без подтверждённой оплаты в отчёт
могут не попасть — это ограничение WB.

## Следующие шаги

Метод `products/history` покрывает только последнюю неделю. Поэтому дневная история
загружается через `products` с однодневным периодом и пагинацией до 1000 карточек.
Окно WB — 365 дней; PERK запрашивает 360 с запасом на время загрузки. Для базового токена
лимит — 2 запроса в час, для остальных — 3 в минуту; полная история не мгновенная.
Первый месяц публикуется после полной загрузки, дальнейшая история — недельными порциями.
Обновление последних 30 дней — каждые 6 часов, сверка 90 дней — еженедельно.
Существующее расписание нужно повторно сохранить с `funnel` в источниках: миграция
сама не включает дополнительные запросы к WB для уже подключённых магазинов.

1. **Дополнения воронки** — CSV `DETAIL_HISTORY_REPORT` с подпиской «Джем» для ускорения
   истории; сверка на реальном кабинете. Сейчас используется только `products`, scope `analytics`.
2. **Заявки покупателей** — после подтверждения права токена (см. выше).
3. **Реклама WB** — `GET advert-api /api/advert/v2/adverts`, `GET /adv/v3/fullstats`,
   `GET /adv/v1/upd` (история затрат). Расходы рекламы — в чистую прибыль и ДРР по товарам.
4. **Поставки и приёмка WB** — `POST supplies-api /api/v1/supplies`, `GET /api/v1/supplies/{ID}/goods`,
   `GET /api/tariffs/v1/acceptance/coefficients`; платное хранение и приёмка —
   асинхронные отчёты `paid_storage` и `acceptance_report`.
5. **Ozon Seller** (`Client-Id` + `Api-Key`): товары `/v3/product/list`, `/v3/product/info/list`;
   отправления `/v3/posting/fbo/list`, `/v4/posting/fbs/list`; остатки `/v4/product/info/stocks`,
   `/v1/analytics/stocks`; финансы `/v1/finance/accrual/postings`, `/v1/finance/accrual/types`, `/v1/finance/accrual/by-day`;
   возвраты `/v1/returns/list`; аналитика `/v1/analytics/data`.
6. **Ozon Performance** (OAuth client credentials): `/api/client/campaign`,
   `/api/client/statistics/daily`, `/api/client/statistics/expense`.
7. **Репрайсер** — только после загрузки цен (`/api/v2/list/goods/filter` WB,
   `/v5/product/info/prices` Ozon) и юнит-экономики; изменение цен — отдельным решением.

Внешняя аналитика конкурентов в план не входит.
