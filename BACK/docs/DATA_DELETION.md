# Удаление данных PERK

До появления кнопки удаления запрос принимает администратор проекта. Подтвердить владельца
через его действующий вход с сильным фактором; зафиксировать точный workspace_id/store_id.
Остановить приём новых задач для удаляемого магазина, отключив его подключение.
Сначала сделать защищённую резервную копию. Не просить присылать API-ключи или пароли.

Из контейнера миграций, под ролью администратора БД:

```
python -m scripts.delete_data --workspace WORKSPACE_UUID --store STORE_UUID
python -m scripts.delete_data --workspace WORKSPACE_UUID --store STORE_UUID --execute --confirm STORE_UUID
```

Первая команда только показывает число строк. Для всего пространства убрать --store и
подтвердить WORKSPACE_UUID. Рабочие данные этой процедурой автоматически не удаляются.
После исполнения проверить нулевые счётчики, отключить сохранённые устройства уведомлений
по запросу владельца и отозвать ключи в кабинетах WB/Ozon. Возобновлять старые задачи нельзя.

Для удаления аккаунта сначала обработать все пространства, где он владелец, либо передать
их другому владельцу по отдельной проверенной процедуре. Затем удалить его членства,
приглашения и персональные записи по FK и самого пользователя под ролью администратора.
Запись об удалении хранит только идентификатор цели и результат, без коммерческих данных.
Резервные копии имеют ограниченный срок хранения (30 дней); после восстановления повторно
применить журнал удалений перед открытием доступа. Эти правила распространяются и на Redis:
остановить задачи, удалить относящиеся к цели зашифрованные кэши либо дождаться их TTL
при отозванном доступе. Рабочие данные не должны возвращаться из бэкапа.

Историю успешных синхронизаций нельзя удалять по произвольному сроку: она подтверждает
покрытие финансов и воронки. Удаляются только старые неуспешные/брошенные данные,
не используемые опубликованными агрегатами. Диагностика импорта хранится 90 дней.
