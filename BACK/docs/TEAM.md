# Команда и права доступа — 29 октября 2026

В приложении: **Ещё → Команда** (владелец или администратор).
Роли — готовые наборы, у ограниченных сотрудников можно менять отдельные права и магазины.

| Роль | По умолчанию |
| --- | --- |
| Владелец (`owner`) | Все функции и магазины |
| Администратор (`admin`) | Все функции и магазины, включая управление командой |
| Менеджер (`manager`) | Аналитика, товары и остатки |
| Бухгалтер (`accountant`) | Аналитика, финансы, себестоимость, расходы, налоги, экспорт |
| Наблюдатель (`viewer`) | Просмотр аналитики, товаров, финансов и прибыли |

Создателя команды нельзя исключить или понизить. Передача владения пока не реализована.
Администратор имеет все бизнес-функции; проверка свежего кода для важных операций сохраняется.

## Приглашение

1. Администратор указывает email, роль, права и магазины.
2. Сотрудник открывает ссылку из письма (7 дней), входит либо регистрируется с этим email.
3. Подтверждает почту и телефон, принимает приглашение.
4. Команда выбирается автоматически; при нескольких командах выбор доступен в профиле.

Регистрация по приглашению не создаёт пустую собственную команду. Существующий пользователь
сохраняет доступ к другим своим командам. Вход по чужому email, просроченная или отменённая ссылка
не дают доступ. Повторная отправка заменяет старый код. Повторное принятие не меняет текущие права.

`TEAM_INVITE_URL` — адрес страницы `/invite`; код передаётся фрагментом `#code=`.
Если приглашение отправлено браузером с Origin из CORS_ORIGINS, письмо ведёт
на `/invite` этого же фронтенда. Запрос без Origin использует TEAM_INVITE_URL:
мобильные ссылки сохраняются. Неизвестный Origin не меняет адрес письма;
CSRF и проверка прав продолжают выполняться независимо.

В production требуется HTTPS. В локальной Wi-Fi разработке адрес должен содержать IP компьютера,
а его origin должен присутствовать в `CORS_ORIGINS`. Мобильная страница приглашения
на Expo-порту открывает Expo Go в разработке и `perk://invite` в установленном приложении.
Сайт на Next.js принимает приглашение в браузере. Телефон и компьютер должны видеть
соответствующий фронтенд и API. Почта использует настроенный провайдер; в текущей dev-среде это Mailpit
на `http://localhost:8025`. Настоящая внешняя доставка требует SMTP-провайдера.

## Права

- `analytics.read` — заказы, выкупы, воронка.
- `inventory.read` — товары, остатки и поставки.
- `finance.read` — выручка, удержания и расходы.
- `profit.read` — себестоимость и прибыль (включает финансы).
- `costs.write` — загрузка себестоимости (включает просмотр прибыли).
- `expenses.write` — изменение своих финансовых расходов (включает финансы).
- `taxes.write` — налоговые настройки (включает просмотр прибыли).
- `reports.export` — разрешение экспорта; новые экспортные маршруты должны проверять его явно.

`permissions: null` использует роль по умолчанию, `[]` закрывает все разделы.
`store_ids: null` — все магазины, включая будущие; `[]` — ни одного.
У owner/admin ограничения игнорируются. Прибыль и себестоимость вырезаются из ответа API
без `profit.read`; скрытие кнопок не является границей защиты.

## API

Префикс `/api/v1`.

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET | `/workspaces/{id}/team` | owner/admin |
| POST | `/workspaces/{id}/invites` | owner/admin + свежий код |
| POST | `/workspaces/{id}/invites/{invite_id}/resend` | owner/admin + свежий код |
| DELETE | `/workspaces/{id}/invites/{invite_id}` | owner/admin |
| POST | `/invites/preview` | Код в теле `{code}`, без входа |
| POST | `/invites/accept` | Подтверждённые email и телефон |
| PUT | `/workspaces/{id}/members/{user_id}` | owner/admin + свежий сильный фактор |
| DELETE | `/workspaces/{id}/members/{user_id}` | owner/admin; самостоятельный выход |

Тело приглашения: `{email, role, permissions?, store_ids?}`. Изменение доступа — то же без email.
Выдача полного доступа требует сильного фактора. Отправка ограничена 20/сутки на команду,
повторная отправка — 3/час на приглашение. Сбой почты возвращает `email_unavailable`,
приглашение остаётся в списке для повторной отправки.

## Защита и эксплуатация

Миграция `0018_team_permissions` расширяет FORCE RLS, проверяет выбранные магазины,
ограничивает записи финансов отдельными разрешениями. Новые API-операции закрыты
для сотрудников, пока не внесены в каталог `accounts/access.py`.

Actor `perk.user_id` устанавливается на транзакцию после проверки сессии. Runtime-роль
остаётся `NOSUPERUSER NOBYPASSRLS`. Фиксированные SECURITY DEFINER функции проверяют
приглашение, членство, права и блокировку магазина; они не принимают произвольный SQL.
Ключи магазина доступны только полным ролям. Фоновые задачи повторно проверяют owner/admin;
уведомления проверяют актуальные права перед выдачей и отправкой.

Права проверяются сервером при каждом запросе. Мобильный клиент обновляет метаданные
каждые 30 секунд и после изменений, разделяет кеш по правам и не сохраняет grants на диск.
Уже просмотренную информацию с устройства отозвать невозможно.

Перед миграцией рабочей БД нужен backup. Автоматический downgrade намеренно запрещён:
старые политики не умеют безопасно представлять новые ограниченные роли. Для отката
восстановите согласованную пару приложения и базы из резервной копии.
