# Карточки товаров — 02.11.2026

## Объединение как на площадке

Каталог PERK повторяет группы маркетплейса внутри выбранного магазина:

- WB: один `imtID` → одна карточка. Нормализованное поле — `group_id`.
- Ozon: подготовленный адаптер сохраняет `model_info.model_id` в то же `group_id`; полноценный коннектор Ozon пока не реализован.
- Без положительного ID группы каждый исходный товар показывается отдельно. Пустые, нулевые и некорректные значения не объединяются друг с другом.
- Явное ручное объединение или разделение в PERK имеет приоритет и сохраняется при следующих импортах.

Названия, артикулы продавца, бренд, категория, фото и характеристики не используются для догадок о модели. Товары в разных группах площадки не объединяются автоматически, даже если выглядят одинаковыми. Товары внутри одной группы площадки не разделяются автоматически из-за различий в характеристиках или названиях. Если сама площадка объединила разные модели, PERK отражает это объединение; исправить его можно вручную.

`group_cards` принимает каталог одного магазина. Сервис обрабатывает магазины отдельно, а ID итоговой карточки содержит ID магазина. Поэтому одинаковые `imtID`, артикулы или ID моделей в разных кабинетах не смешиваются.

## Контракт

- GET `/api/v1/workspaces/{workspace_id}/product-models`: список карточек, вложенные исходные товары `products`, размеры `variants`, фото, остатки и себестоимость. Название эндпоинта и тип `ProductModel` сохранены для совместимости; в интерфейсе используется «Карточка товара».
- `grouping`: `marketplace` — группа площадки, `manual` — явный выбор пользователя, `single` — отдельный товар без ID группы. Прежнее значение `automatic` заменено на `marketplace`; OpenAPI и сгенерированный клиент обновлены, ключ кэша фронта изменён.
- Поиск выбирает карточку целиком со всеми вариантами; пагинация применяется после объединения. Фильтры: магазин, поисковая строка, наличие, отсутствие цены.
- Исходный GET `/products` сохранён для выбора отдельных артикулов и совместимости.
- POST `/stores/{store_id}/product-grouping`: `{articles: ["42", "43"], title: "Название карточки"}`. Только владелец/администратор. Один артикул закрепляет отдельную карточку. Несколько закрепляют выбранные артикулы в новой ручной группе внутри одного магазина, категории, типа и бренда. Повторное объединение заменяет прежнее назначение выбранных артикулов.

Ручные назначения хранятся в `catalog_overrides` с FORCE RLS, шифрованием названия и аудитом. Новая миграция для перехода не нужна. Цены, складские количества и финансовые записи остаются у исходных артикулов и штрихкодов.

## Интерфейс

Карточка содержит фото со свайпом, выбор варианта и размера, остатки, себестоимость и историю цен. Одинаковые цвета различаются по артикулу, при совпадении артикула — по ID товара. Если название выбранного варианта отличается от заголовка группы, оно показывается отдельно. Это позволяет различать варианты без попыток угадывать модель.

## Синхронизация

Фото и ID группы берутся из штатного импорта каталога. Уже сохранённые `group_id` используются сразу; перезагружать финансовые отчёты не требуется. После следующих импортов PERK отражает изменения объединений на площадке с учётом ручных исключений.

Для группировки не нужны справочники `isVariable`/`is_aspect`. Их автоматическая загрузка после импорта каталога отключена, чтение списка не зависит от Redis-справочника. Старые задачи справочника зарегистрированы для совместимости с уже отправленными сообщениями; штатный импорт больше их не запускает.
