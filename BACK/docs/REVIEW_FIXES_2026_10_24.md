# Исправления после мобильной проверки

## Вход и загрузка

`auth/router.py`: блокировки пользователя — `FOR NO KEY UPDATE`, а не `FOR UPDATE`.
Они всё ещё сериализуют изменения аккаунта, но не конфликтуют с `KEY SHARE` внешних
ключей фоновой загрузки. Регрессионный тест держит `KEY SHARE` и выполняет вход.

Расчёт/публикация также блокируют магазин через `NO KEY UPDATE`: связанные очереди
могут обновлять своё состояние, не ожидая FK-блокировки. Загрузчик использует
`SKIP LOCKED`: при занятости магазина сохраняет курсор и переносит попытку без увеличения
счётчика ошибок (`sync_store_busy`). Регрессионный тест держит блокировку магазина,
проверяет отсутствие потери курсора и успешное продолжение после освобождения.

`sync/planner.py`: финансовая история публикуется порциями максимум по 31 дню, от свежих
дат к старым. Ограничение применяется и к старым расписаниям с chunk=3650. Если
`sync_size_limit` уже уменьшил порцию, меньший размер сохраняется.

`finance/report.py`: preview использует опубликованные дни вне затронутых preview дат.
Каждый день берётся только из одного набора; опубликованные суммы и preview за один день
не складываются. COGS и прибыль неполного импорта остаются неизвестными. Старая проекция
доступна, пока новая строится, но не заявляет полное покрытие. Версия Redis-кэша — v5.

`inventory/router.py`: StockForecast наследует `demand_basis=orders|buyouts`, вместо
ошибочного переопределения только `buyouts`, вызывавшего ValidationError при наличии заказов.

## Баланс WB

Миграция `0016_wb_balance`: источник `balance` для расписаний/записей. Для существующих
включённых финансовых расписаний добавляется расписание баланса.

- Официальный GET `https://finance-api.wildberries.ru/api/v1/account/balance`.
- Категория токена `finance`, только чтение. Decimal-строки current/for_withdraw,
  валюта и время получения; отсутствие поля не считается нулём.
- Периодическое обновление раз в 15 минут; квота на профиль/тип токена:
  61 секунда для personal/service, консервативно сутки для basic. Заголовки WB
  могут увеличивать ожидание. Смена токена не сбрасывает квоты.
- `GET /workspaces/{workspace_id}/stores/{store_id}/finance/balance` — чтение сохранённого
  баланса, не синхронный вызов WB.

## Весь бизнес

`GET /workspaces/{workspace_id}/business?date_from=...&date_to=...`

- `store_id` ограничивает отчёт одним магазином; иначе все видимые активные магазины
  текущего пространства. Членство и RLS применяются к каждому чтению.
- `currency` (по умолчанию RUB) — валюта финансового отчёта. Балансы возвращаются отдельными
  группами по валюте. Суммы WB statistics без валюты не складываются между кабинетами.
- `topic=overview|sales|orders|profit|buyouts|funnel|stock` выбирает дополнительные показатели.
- Данные берутся только из хранимых отчётов/снимков, никогда напрямую из WB. Снимки
  за 7/30/90 дней на клиенте предзагружаются и сохраняются локально.
- Ответ: суммарные финансы/дни, количества заказов/выкупов/отмен, балансы, показатели темы,
  список магазинов с их цифрами, количество полностью готовых магазинов.
- Деньги суммируются Decimal, проценты пересчитываются только при полном покрытии.
  Товары не объединяются по nm_id между магазинами: см. stores[].finance.products.
- Неполный магазин не превращается молча в ноль. Готовность и список исходных магазинов
  позволяют интерфейсу показать известную часть. Разные рабочие пространства не объединяются.

OpenAPI экспортируется `python -m scripts.export_openapi`; фронтенд генерирует Orval заново.
