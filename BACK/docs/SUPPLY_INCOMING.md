# Оформленные партии в расчёте потребности

Общий серверный расчёт для сайта, мобильного приложения, CSV и новых планов.
Внутренние черновики и планы PERK не считаются поставками маркетплейса.
Изменений таблиц и миграций не требуется. Существующие сохранённые планы не пересчитываются.

## Состав и идентификаторы

WB: GET /api/v1/supplies/{ID}/goods, limit 1000, offset, isPreorderID.
Состав группируется по точному nmID, варианты и штрихкоды одной модели суммируются.
В каждой задаче остаётся один запрос с существующим общим лимитером WB.
После всех страниц повторно читается карточка поставки. При изменении карточки
чтение перезапускается до двух раз, затем завершается ошибкой без публикации.
Количество по составу должно совпасть с количеством партии.
Дубликаты штрихкодов, незавершённая пагинация, ошибки и превышение лимитов
не заменяют предыдущий успешный набор. Поля телефонов, адресов и стоимости
приёмки не входят в сохраняемые записи или курсоры.

Ozon: уже используемый /v1/supply-order/bundle теперь сохраняет пары SKU/quantity,
а не только сумму. Сопоставление исключительно с channel_skus.fbo конкретного
кабинета; FBS SKU, offer_id, названия и артикулы продавца для этого не подставляются.
Старый кеш без состава перечитывается, включая возобновлённые контрольные точки.
Дубликаты SKU и нарушения пагинации завершают импорт ошибкой без замены снимка.

## Какие партии учитываются

- WB: статусы 2 «Запланировано» и 3 «Отгрузка разрешена».
- Ozon: READY_TO_SUPPLY, ACCEPTED_AT_SUPPLY_WAREHOUSE, IN_TRANSIT.
- Исключаются отменённые, отклонённые, черновики, приёмка и принятые партии.
  WB 6 «Отгружено на воротах» исключён: это не подтверждение нахождения в пути.
  Если уже есть факт приёмки или принятые/размещённые/разгружаемые единицы,
  партия не вычитается, чтобы не пересечься с доступным остатком.
- Снимок и проверка состава конкретной партии должны быть не старше двух
  часов. У WB время проверки записывается после повторного чтения карточки:
  длинный импорт не делает старые партии свежими и не обесценивает последнюю
  только что проверенную партию. Это особенно важно при редкой квоте WB.
- Если снимок поставок старше снимка остатков, вычет не применяется:
  часть этой партии уже могла войти в новые остатки.
- Без полного нативного состава количество не разносится предположительно.

## Даты и расчёт

Плановая дата API — запись на отгрузку/приёмку, а не обещанная дата доступности.
Оценка доступности партии: плановая дата + выбранный продавцом срок доставки
и приёмки. Для Ozon это также запас на перемещение из пункта сдачи.
Это плановое допущение, а не нативный прогноз маркетплейса.

Для WB и ещё не отгруженной партии Ozon прошедшая плановая дата не вычитается.
У Ozon с подтверждённым статусом движения прошедшая дата сдачи допустима,
пока оценка доступности (эта дата + срок продавца) ещё не прошла. Дата не
переносится на сегодня заново. Просроченная оценка или неизвестная дата
оставляют количество «В поставках», но не уменьшают новую потребность.
Будущая партия за пределами горизонта также не уменьшает рекомендацию.

Новая поставка планируется через L дней с покрытием T дней после приезда.
До дня L текущий остаток расходуется по нативному среднесуточному спросу,
остаток не уходит ниже нуля: потерянные заказы не накапливаются.
После L расчёт находит минимальное дополнительное количество, которое
покрывает спрос до L+T с учётом дат уже оформленных партий. Поздняя партия
не может покрыть дефицит до её приезда. Округление до коробов — последним шагом.

Пример: остаток 0, спрос 5 шт./день, L=7, T=30. Уже оформлено 100 шт.,
доступных на день 20. Нужно ещё 65 шт., чтобы покрыть дни 7–20;
простое вычитание 100 из 150 дало бы ошибочные 50.

## Контракт и интерфейс

ReplenishmentItem / PlanLine:
- incoming_quantity: int | null — весь известный объём активных партий товара,
  включая партии с неизвестной/прошедшей датой; null при недоступном, старом или неполном источнике.
- incoming_reduction: int — насколько партии уменьшили потребность ДО коробов.

ReplenishmentOverview:
- incoming_units: int | null — сумма активных партий всех выбранных кабинетов,
  null если хотя бы один источник неактуален или без полного состава.
- incoming_complete: bool — полнота источников состава, не гарантия сроков приезда.

Сайт: колонка «В поставках», в деталях — объём и уменьшение потребности.
Мобильное приложение: те же поля в деталях. Пояснение расчёта скрыто в InfoHint.
CSV потребности содержит оба поля; новые планы сохраняют их в замороженном снимке.
Итоги считаются после вычета и округления, до фильтров, пагинации и экспорта.

Известные ограничения: статус и остатки площадки обновляются неатомарно;
неполные и принимаемые партии пока не вычитаются. Нет ручного обещания даты
доступности и распределения потребности по кластерам. Плановый срок можно
уточнять в дальнейшем; транспортные события не подменяются выдуманной ETA.
