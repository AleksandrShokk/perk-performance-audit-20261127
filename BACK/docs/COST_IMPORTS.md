# Себестоимость из Excel и внешние расходы

Состояние на 8 октября 2026. Ввод финансовых данных и выбор цены для расчётов реализованы.
Предварительная прибыль и ABC подключены: [PROFIT.md](PROFIT.md). Налоги и сверка
специальных операций — отдельный следующий этап.

Все пути ниже начинаются с `/api/v1/workspaces/{workspace_id}/stores/{store_id}`.
Методы требуют действующую сессию с MFA. Браузер передаёт cookie и CSRF-заголовок для
записывающих запросов; мобильный клиент — Bearer. Совмещать оба способа нельзя.
Владелец может добавлять данные, участник с ролью viewer — читать сохранённые цены и расходы.
Отсутствующий доступ возвращает 404, без раскрытия существования чужого магазина.

## Шаблон и правило вариантов

`GET /costs/template`, операция OpenAPI `costsDownloadTemplate`, возвращает XLSX-файл.
Фронтенд предлагает скачать файл; шаблон содержит пустой лист «Себестоимость» и отдельную
инструкцию. Каталог магазина должен быть загружен до импорта. Не менять названия столбцов.

| Столбец | Заполнение |
|---|---|
| Артикул WB | `nm_id` из каталога именно этого магазина. Текст, положительное целое. |
| Баркод (необязательно) | Пустой для общей цены всех размеров; заполненный для отдельного варианта. |
| Себестоимость за единицу | Готовое число, не формула; до четырёх знаков после запятой. Ноль допустим, пустое значение — ошибка. |
| Действует с | Дата `ГГГГ-ММ-ДД` или дата Excel без времени. |
| Валюта | Выпадающий список RUB, USD, EUR, CNY, KZT, BYN, AMD, KGS, UZS в строках 2–5001. Пустая ячейка использует валюту workspace. |

Артикул и баркод хранить как текст, чтобы Excel не удалил ведущие нули и не округлил
длинные номера. Артикул продавца не заменяет `nm_id`. Новая закупочная цена — новая строка
с новой датой; цена на уже сохранённую дату не перезаписывается. Исправление ошибочной
сохранённой цены отдельным управляемым процессом пока не реализовано.

На дату расчёта выбирается последняя действующая цена указанного баркода. Если такой цены
ещё нет — последняя общая цена артикула. Новая общая цена не отменяет отдельную цену размера.
Валюта должна совпадать; конвертация валют не выполняется. Добавление цены задним числом
может изменить расчёты соответствующих прошлых дат; закрытые отчётные периоды ещё не реализованы.

## Загрузка и применение

1. `POST /cost-imports` (`costsPreviewImport`): multipart/form-data, поле `file`.
   Выводит `rows_count`, `valid_count`, `error_count`, `errors`, `items`, `can_apply`.
   В `items` есть номер строки, цена и `action: insert | unchanged`.
2. Фронтенд показывает ошибки по строкам/полям и предварительные изменения. При любой ошибке
   `can_apply=false`, `preview_id=null`: ни одна цена не сохраняется. Исправить файл и загрузить снова.
3. При успешной проверке пользователь нажимает «Применить»:
   `POST /cost-imports/{preview_id}/apply` (`costsApplyImport`). Получает `inserted` и `unchanged`.
   Применение выполняется одной транзакцией; повтор того же запроса возвращает сохранённый результат.

Срок предпросмотра — 30 минут. Перед применением каталог и существующие цены проверяются снова.
Изменения с момента проверки дают 409, истёкший неприменённый предпросмотр — 410.
Повторная загрузка уже сохранённых цен не создаёт дублей. Дубль одной комбинации
артикула/баркода/валюты/даты внутри файла — ошибка; разные даты — история цены.

Ограничения: файл до 256 КиБ, 5000 строк данных, до 12 МиБ распакованного содержимого.
Ответ содержит первые 100 ошибок/строк предпросмотра и полные счётчики. Не более пяти
предпросмотров в минуту и двадцати неистёкших предпросмотров на магазин.
Макросы, вложения, внешние ссылки и формулы на листе себестоимости отклоняются.
Файл не сохраняется на диск и не извлекается из архива; XML обрабатывается с запретом DTD/сущностей.
Для загрузки ограничение HTTP-тела 320 КиБ с учётом multipart; другие API-тела сохраняют предел 64 КиБ.

## Чтение и выбор себестоимости

- `GET /costs` (`costsList`): история цен, `limit` 1–500 (по умолчанию 100), `offset` 0–50000.
- `GET /costs/calculate` (`costsCalculate`): `nm_id`, `at`, необязательные `barcode`, `quantity`, `currency`.
  Возвращает `unit_cost`, `total_cost`, `effective_from`, `matched_by: article | barcode`, `available`.
  При отсутствии цены `available=false`, цены и дата — `null`. Количество по умолчанию 1.

Это умножение действующей цены на количество. Возвраты, прибыль, списание себестоимости,
выбор даты продажи против даты отчёта и восстановление себестоимости возврата учитываются
в следующем финансовом модуле, а не скрыто внутри этого метода.

## Внешние расходы

`POST /expenses` (`expensesCreate`):

- `request_id`: UUID, фронтенд создаёт один раз и повторно использует при сетевом повторе;
- `expense_date`: дата расхода;
- `amount`: положительное число Decimal, до четырёх знаков после запятой;
- `currency`: код валюты; если не указан, валюта workspace;
- `comment`: описание 1–500 символов, например аренда или упаковка.

Повтор с тем же UUID и теми же данными возвращает прежний расход; отличающиеся данные дают 409.
Использованный UUID нельзя повторно использовать после удаления.

- `GET /expenses` (`expensesList`): активные расходы, пагинация как у истории цен.
- `GET /expenses/totals` (`expensesTotals`): обязательные `date_from`, `date_to`, границы включены.
  Суммы и количество сгруппированы по валюте; `allocation: store_only`.
  При более чем 10000 расходах за выбранный период нужно уточнить период, усечённый итог не выдаётся.
- `DELETE /expenses/{expense_id}` (`expensesDelete`): логическое удаление, повтор возвращает 204.

Товарные показатели не получают условную долю аренды/прочих расходов. Общая сводка магазина
вычитает их отдельно в финансовом отчёте. Это позволяет видеть и вклад товаров,
и расходы магазина без выдуманной точности юнит-экономики.

## Хранение и проверки

Миграция `0006_cost_inputs` создаёт `product_costs`, `cost_imports`, `external_expenses`.
Шифрование AES-GCM связывает цену с workspace, магазином, артикулом, баркодом, валютой и датой.
Подмена контекста не позволяет расшифровать цену. Сумма/комментарий расхода и весь предпросмотр
также зашифрованы. В журнал записываются действие и идентификатор, без файла, цен и комментариев.
Включён FORCE RLS: чтение участникам workspace, запись владельцу. Цены append-only;
для runtime нет RLS-политик изменения/удаления существующей цены.

Проверки включают варианты и даты, неизвестную цену, Decimal и ведущие нули, идемпотентность,
ошибки каталога/дубли, отказ всей транзакции, истечение и повторную проверку предпросмотра,
разделение валют, логическое удаление, MFA/роли, чужой workspace/магазин, контекст шифрования
и опасные XLSX. Проверки с PostgreSQL проходят в отдельном одноразовом стеке с искусственными данными.

Схема клиента экспортируется в `docs/openapi.json`. Методы ввода и ответы типизированы;
поля денежных значений в ответах передаются строками. Для multipart в будущем Orval-клиенте
нужно отправить `FormData`, а не JSON и не ручной `Content-Type` без boundary.
