# Исправления аудита PERK от 09.11.2026

Аудит проверял надёжность загрузок WB/Ozon, безопасность доступа и сессий,
нагрузку на API и базу, финансовые расчёты, структуру и неиспользуемый код.
Рекомендации проверены по исходникам и действующим контрактам; изменения внесены
в BACK, FRONT и общие пакеты. Ниже отделены исправления кода от подготовки сервера беты.

## Надёжность данных

| Пункт | Что изменено |
| --- | --- |
| D-01 | Отчёт цен Ozon обрабатывает только нужные отправления/SKU. Нулевая оплата без валюты не блокирует импорт и не превращается в выдуманную цену в рублях: сумма остаётся неизвестной. Некорректный формат цен имеет отдельный код ошибки и ограниченный повтор. |
| D-02 | Ошибки формата WB отделены от ошибок расшифрования и доступа. Плохая строка не объявляет действующий токен недоступным и не отключает его расписание. |
| D-03 | Добавлен карантин `import_issues`: зашифрованный идентификатор и причина, без исходного ответа и персональных данных. Для финансов Ozon нули наследуют только подтверждённую валюту начисления; прочие плохие записи изолируются, день явно частичный. WB сохраняет диагностику и предыдущую успешную публикацию: финансовые строки молча не пропускаются. Диагностика доступна владельцу/администратору через `/stores/{id}/import-issues`. |
| D-04 | Часовой пояс каждого соединения PostgreSQL явно UTC; календарь отчётов сохраняет свои правила дат. |
| D-05 | Общая функция округления денежных значений с Decimal и ROUND_HALF_UP; её используют финансовые и Ozon-расчёты. |
| D-06 | В объединении WB/Ozon не складываются просмотры и корзины с разными определениями. Несопоставимые счётчики и конверсии возвращаются как неизвестные; показатели отдельных кабинетов сохраняются. |
| D-07 | Схемы категорий WB ставятся в очередь после успешной публикации каталога; действует существующий кэш. |

## Безопасность

| Пункт | Что изменено |
| --- | --- |
| S-01 | Обычные авторизованные запросы дополнительно ограничиваются по пользователю, а не общему адресу прокси. Лимит входа по IP сохранён. Добавлен пример production TLS-прокси с прямым маршрутом API и очисткой подставленного X-Forwarded-For. |
| S-02 | Включены ENABLE/FORCE RLS для пяти таблиц из аудита и новой диагностики. Очереди меняют только уполномоченные владельцы/администраторы; уведомления видит получатель. Диспетчеры используют ограниченное обнаружение владельцев, затем обычную RLS и выбор только их собственных задач. Отозванный доступ и устаревшая задача не обходят изоляцию. |
| S-03 | Web Locks координируют refresh между вкладками; сохранена защита от ответов старой сессии. Безопасная коллизия недавней ротации получает 409 без выдачи токенов и без отзыва действующей сессии. Старый повтор и мобильный replay по-прежнему отклоняются. |
| S-04 | Удалены устаревшие `wb-connect.json`, `perk-access-token.tmp`, открытый POSTGRES_PASSWORD и неиспользуемый API_BIND_HOST. Пароли остаются в предназначенных для них файлах секретов. Старые внешние ключи автоматически не отзывались: это могло отключить действующий магазин. Дальнейшие действия перечислены ниже. |
| S-05 | Документирована ручная процедура удаления магазина/пространства/аккаунта. Добавлен административный инструмент с предварительным подсчётом по умолчанию и точным подтверждением UUID; удаление идёт по зависимостям, остаётся минимальное событие аудита. В тесте проверено реальное удаление только тестового пространства. Добавлена ограниченная очистка старой диагностики, завершённого staging и неуспешных запусков, не используемых агрегатами. История успешных импортов сохраняется для проверки покрытия отчётов. |
| S-06 | Ответы API и отчёты мобильного приложения больше не сохраняются открытым текстом в AsyncStorage. Новый buster удаляет прежний дисковый кэш; кэш в памяти и очистка при выходе сохранены. |
| S-07 | Добавлена Content-Security-Policy с новым nonce на каждый документ. Подключены штатные скрипты Next и темы; запрещены сторонние inline-скрипты, object и встраивание страницы. Для существующих динамических стилей оставлен style-src unsafe-inline; unsafe-eval разрешён только в разработке. Проверено в Edge. |
| S-08 | Рабочая мобильная сборка отказывается использовать API по HTTP. Локальная разработка на телефоне продолжает работать. |
| S-09 | При подключении первого сильного фактора на подтверждённую почту отправляется одноразовая ссылка отмены на 24 часа. Она привязана к состоянию фактора, хранится зашифрованно и передаётся во фрагменте URL. Отмена удаляет этот способ подтверждения/резервные коды и отзывает все сессии. Это ограниченное окно восстановления, а не гарантия защиты при полном контроле злоумышленника над почтой. |

## Производительность и структура

Прогресс сначала 5 секунд, затем 15, с замедлением при множестве кабинетов. WB перечитывает отчёт по изменению ревизии; лишний опрос прошлого периода и сводки при активной загрузке остановлен. |

| P-05 | Безопасность роли БД проверяется при создании соединения и сохраняется в его метаданных. Убран повторный SQL к pg_roles на каждый API-запрос; небезопасная роль по-прежнему блокируется. |
| A-01 | Подготовлены локальные Git-снимки FRONT и BACK. Добавлен CI фронта: установка по lockfile, lint, типы, тесты, сборка сайта и аудит всех зависимостей. Ничего не отправлялось в удалённый репозиторий. |
| A-02 | Python-каталог прав и ролей включён в OpenAPI; TypeScript генерируется из него. Согласованность с SQL проверяется тестом, чтобы изменения не расходились незаметно. |
| A-03 | Отформатированы четыре указанных теста и остальные изменённые Python-файлы; Ruff проходит. |
| A-04 | Добавлены явные схемы ответов capabilities и legacy analytics; обновлены OpenAPI, TypeScript и Zod. |

Удалены подтверждённо неиспользуемые `useOverview`, `ActivityChart`, `supplies-card`,

Подробные журналы находятся в локальной папке `outputs/audit-fixes-20261109`.
Рабочая база предварительно сохранена в локальную резервную копию. Миграции 0036–0041

## Что необходимо при подготовке сервера беты

1. Настроить настоящий домен, TLS-сертификат и доверенный адрес прокси по `deploy/README.md`.
   Это изменение локального проекта не публикует его и не устанавливает сертификат на будущий сервер.
2. Если удалённые старые копии содержали ещё действующие ключи, перевыпустить соответствующий
   ключ в кабинете WB и заменить его в PERK; старую пользовательскую сессию завершить.
   Удаление файла само по себе не отзывает внешний ключ. Содержимое токенов в отчёт не включалось.
3. Ранее разрешённый HTTP-доступ по Wi-Fi оставлен для разработки. Для реальных участников беты
   использовать HTTPS, рабочие каналы доставки кодов и резервные копии с ограниченным доступом.

Ручное удаление данных выполняется администратором по `docs/DATA_DELETION.md`;
кнопка самостоятельного удаления в интерфейс не добавлялась. Числа реальных отчётов здесь
не пересверялись с кабинетами маркетплейсов: тесты проверяют контракты, изоляцию и расчётные сценарии.
