# PERK Backend

Python-бэкенд аналитики собственных магазинов маркетплейсов.
**8 октября 2026: локальная приватная бета, доступна для подключения первых экранов фронтенда.**
Wildberries подключён. Ozon, поставки и реклама — следующие этапы.
Публичное размещение и независимая финансовая сверка ещё не завершены.

## Что работает

- Открытая регистрация с кодом на почту, вход паролем + код в Telegram/SMS (без телефона —
  на почту), приложение-аутентификатор по желанию, recovery-коды, подтверждение опасных
  действий, сброс пароля, web cookies/CSRF, мобильные токены, выход и ротация refresh.
- Workspace, роли, принудительная RLS и ограниченная роль БД.
- Команда: приглашения сотрудников по почте, owner/viewer, исключение и выход из кабинета;
  защита создателя и tenant-метаданных на уровне PostgreSQL. [Контракт](docs/TEAM.md).
- Единый JSON-формат ошибок (старый detail сохранён), X-Request-ID и связь запросов с задачами.
- WB с read-only токеном; шифрование ключей и данных магазина.
- Каталог, продажи/возвраты, FBW-остатки, финансы, продолжение загрузок и автообновление.
- Дневная аналитика, история продаж из финансовых отчётов, ABC по количеству, кэш.
- Себестоимость из Excel: выбор валюты, предпросмотр/применение, варианты и история цен.
- Отдельные внешние расходы магазина.
- Предварительная прибыль до налогов, дни для графиков, товарный вклад и ABC по выручке/вкладу.
  При неполных данных результат остаётся неизвестным, а не нулевым.
- Главный экран одним запросом, аудит потерь, юнит-экономика, симулятор цены, налоги и
  чистая прибыль, прогноз остатков, план поставок, история остатков, сезонность,
  журнал событий, план/факт. Отчёты заранее считаются в фоне и открываются мгновенно.
- Уведомления: лента, утренняя сводка и тревоги в Telegram-боте и push.

[Текущий статус](docs/STATUS.md) · [План](docs/ROADMAP.md) ·
[Памятка для фронта](docs/FRONTEND_HANDOFF.md) · [Проверки](docs/VALIDATION.md).
Репозиторий не содержит токенов, паролей, базы или выгрузок подключённого магазина.

## Стек

Python 3.14, FastAPI, Pydantic, SQLAlchemy/Alembic, PostgreSQL 17, Redis 7.4, Celery,
Argon2, AES-GCM, Docker Compose, uv. Версии зафиксированы в uv.lock.
Фронтенд: Expo / Next.js / TanStack Query / Orval.

## Запуск на Windows

Нужен Docker Desktop с Linux-контейнерами. PowerShell из папки проекта:

```powershell
# Только при первом запуске, если файлов ещё нет:
Copy-Item .env.example .env
docker run --rm --network none --mount "type=bind,source=$PWD,target=/workspace" --workdir /workspace python:3.14-slim-bookworm python -m scripts.init_security

docker compose up -d --build
```

Если Python уже установлен: `python -m scripts.init_security` вместо docker run.
Скрипт сохраняет существующие секреты. `.env` и `.secrets/` исключены из Git.
Не заменяйте ключи шифрования существующей базы: данные станут нечитаемыми.
На Windows ограничьте доступ к `.secrets` текущим пользователем и системными администраторами.

Compose ждёт базу и Redis, применяет миграции, запускает API, worker и beat.
Успешный migrate имеет статус Exited (0).

```powershell
docker compose ps -a
docker compose exec api python -m scripts.check_worker
docker compose run --rm migrate alembic check
```

- Документация: http://localhost:8000/docs
- Схема: http://localhost:8000/openapi.json
- Готовность: http://localhost:8000/api/v1/health/ready

API опубликован только на 127.0.0.1:8000. База и Redis доступны только контейнерам.
Для разработки Python на компьютере:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml up -d
```

Это открывает PostgreSQL на 127.0.0.1:5434, Redis на 127.0.0.1:6381 и локальный почтовый
ящик Mailpit на http://127.0.0.1:8025 — письма с кодами никуда не уходят.
Доступ с телефона в той же Wi-Fi сети включается отдельным файлом (адрес компьютера —
`API_LAN_HOST` в `.env`):

```powershell
docker compose -f compose.yaml -f compose.lan.yaml up -d
```

Это обычный HTTP: только тестовые аккаунты, без реальных паролей и токенов магазинов.
Не открывайте базу или консоль в интернет. В production API работает за TLS-прокси;
его адрес задаётся в `FORWARDED_ALLOW_IPS`, иначе заголовки прокси игнорируются.

## Регистрация и коды

Регистрация открытая: `POST /api/v1/auth/register`, затем код из письма.
Web использует client=web, cookies/CSRF; мобильный клиент — client=mobile и Bearer.
Бизнес-маршруты требуют подтверждённого входа, подключение магазина — телефон или
приложение-аутентификатор. Порядок: [FRONTEND_HANDOFF.md](docs/FRONTEND_HANDOFF.md).

Куда приходят коды локально:

| Канал | По умолчанию | Настройка |
|---|---|---|
| Почта | `docker compose logs api` (или Mailpit с compose.dev.yaml) | `EMAIL_PROVIDER=smtp`, `SMTP_*`, `EMAIL_FROM` |
| Telegram | лог api | `TELEGRAM_PROVIDER=gateway`, `TELEGRAM_GATEWAY_TOKEN_FILE` — файл с токеном Telegram Gateway (отправка на свой номер бесплатна) |
| SMS | лог api | реальный провайдер подключается позже; в production тестовые провайдеры запрещены |

Production требует SMTP с шифрованием и запрещает провайдеры, пишущие коды в лог.

## Ежедневная работа

```powershell
docker compose up -d --build
docker compose logs --tail=100 -f api worker migrate
docker compose run --rm migrate
docker compose down
```

Обычная остановка сохраняет тома. Не удаляйте их, если нужны данные.
Миграции создаются через Alembic и проверяются до применения. Admin-контейнер применяет
миграции отдельно; API не получает привилегированную роль.

## Локальная консоль

Экран разработчика на 127.0.0.1:8010 запускается отдельно через compose.console.yaml.
Ключ и привязка к магазину создаются локально, исключены из Git. Ключ не принимается
основным API; консоль запрещена в production. Инструкция: [DEV_CONSOLE.md](docs/DEV_CONSOLE.md).

## Проверки

GitHub Actions проверяет стиль, тесты, миграции, Bandit и OpenAPI в отдельной базе
со случайными временными секретами. Интеграционные тесты не запускаются на рабочей базе.

После `uv sync --locked` проверки без базы:

```powershell
uv run ruff check .
uv run ruff format --check .
uv run pytest -m "not integration" -p no:cacheprovider
```

Контейнерные тесты запускайте только в отдельном Compose-проекте с тестовыми томами
и секретами. Не используйте проект с реальными магазинами.
Результаты: [VALIDATION.md](docs/VALIDATION.md).

## Перед production

Нужны HTTPS, резервное копирование/восстановление, управление ключами, мониторинг,
независимая проверка безопасности и финансовая сверка. Доступ разработки отзывается,
консоль и её файлы не размещаются публично. Проверки production-настроек не заменяют аудит.
